Contract: as ADR-0002 s5. Stored citation ids = chunk ids (JSON) / doc ids (stream). Only completed (`done`) answers are stored; abstentions, budget stops and errors are not. `run_agent` receives `history` only when non-empty (existing test stubs keep working). Schema version stays 2 (already 2 from failure_reason); tables are CREATE IF NOT EXISTS.
Edge cases: expired == unknown (404); concurrent appends are one transaction; FKs pragma is off so deletes are explicit.
Known gaps: retrieval query is not rewritten from history (prompt-level only, per brief); a follow-up whose retrieval is weak may still abstain. No per-owner session count cap (T-022).
New env vars for the human to add to .env.example: SESSION_MAX_MESSAGES=20, SESSION_MAX_TOKENS=2000, SESSION_TTL_HOURS=24.
See it: `pytest -q tests/test_sessions.py`; POST /v1/sessions, then POST /v1/query with that session_id.
Review round 1 fixes: non-stream store fault is logged and the answer still returned; each stored message capped at SESSION_MAX_TOKENS*2 chars (with a truncation marker) and the newest turn is never dropped by `_bound`; owner/live check now inside `BEGIN IMMEDIATE` with the writes; index on `sessions.expires_at` and lazy purge throttled to once per 60 s (startup and explicit `purge_expired()` always run; reads still treat expired as unknown); `run_agent` always receives `history` (test stubs take **kw); 6 new tests. Note: the stream path stores doc ids, the JSON path stores chunk ids.
