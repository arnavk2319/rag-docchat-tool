## Findings (implementer)
Files: new `src/backend/app/core/limits.py`, `store/spend.py`, `tests/test_limits.py`; changed `api/deps.py` (ApiError headers, `llm_guard`, `QueryLease`/`SummarizeLease`), `api/query.py`, `api/sse.py`, `api/summarize.py`, `api/sessions.py`, `services/agent/graph.py` (`budget_out`), `services/summarization.py` (`budget_out`), `store/sessions.py`, `core/config.py`, `main.py`, `tests/test_logging.py`, `tests/test_regressions.py`, docs (security, overview, ai-design).
Contract: 429 `rate_limited` (+`Retry-After`), 429 `spend_cap_exceeded`, 429 `session_limit_exceeded`, all `{detail, code}`; `X-RateLimit-Limit/Remaining/Reset` on /v1/query and /v1/summarize responses (incl. SSE) and on limit rejections. Rate limits run in a dependency; the daily-cap reservation (`Guard.acquire`) runs in the handler after validation and before any stream or LLM call. Also 429 `global_rate_limited` and `global_spend_cap_exceeded`. Spend in table `daily_spend(owner_id, day UTC, usd)`; reserve per-run max USD, settle with actual Budget.usd in `finally` (non-stream, summarize) or when the stream generator ends (covers disconnect/cancel/budget stop).
Env vars for the human to add to `.env.example` (protected, NOT edited): `RATE_LIMIT_PER_MIN=30` (per user per minute, >0), `DAILY_USD_CAP=1.0` (per user per UTC day; must be > 0, 0 is rejected at startup), `GLOBAL_DAILY_USD_CAP=5.0` (all users, > 0), `GLOBAL_RATE_LIMIT_PER_MIN=120` (all users, > 0), `SESSION_MAX_PER_OWNER=100`. (`RATE_LIMIT_PER_MIN`/`DAILY_USD_CAP` already existed in Settings.)
Log audit fixes: removed `log.exception` (3 sites, now class name only), `main.py` HTTPException handler logs detail only for ApiError. Existing test_regressions log test adjusted accordingly.
Edge cases: cap check also blocks abstain-only requests (no LLM) when cap reached; rate-limit hits count even for later 404/422 errors; non-stream query meters spend through a no-limit tracking Budget (behaviour unchanged).
Known gaps: per-process limiter/reservations (multi-worker needs shared store); calls that fail with no usage are not charged; stored-document cap not implemented; X-User-Id is still the temporary auth.
See it work: `uv run pytest -q tests/test_limits.py tests/test_logging.py`.
