## Review (reviewer)

verdict: changes-requested (round 1)
Verified: `ruff check` clean, `pytest -q` 1068 passed / 5 skipped. Mint route is the only public /v1 route (test exempts exactly that path); token_expired raised only after signature check; 401 body keeps {detail, code}; owner ids `anon-<96-bit hex>`; demo validator rejects default; caps override applied in acquire before LLM call; existing-test edits are expectation-only; deploy.md rows match config; openapi drift test passes; no TTL secret added.
1. [should] src/backend/app/api/auth_anon.py:35 IPv6 not normalised. Each /128 is a separate limiter key, so any host with a /64 bypasses the per-IP mint limit, and rotating addresses fills the 10k-entry table (core/limits.py MAX_TRACKED_USERS), after which new legit IPs get 429 rate_limited (mint DoS). Spend stays bounded by the demo tenant cap, so this is availability/abuse, not cost. Fix: key IPv6 by /64 (ipaddress.ip_network(f"{ip}/64", strict=False)), unmap IPv4-mapped (::ffff:a.b.c.d) to v4; add a test.
2. [nit] tests/test_auth_anonymous.py:85-97 test_demo_caps: the `pytest.raises` block holds two acquires; first succeeds silently so the intent is unclear. Split into one acquire that succeeds and one that raises.
3. [nit] core/limits.py `tenant_caps` keyed by tenant string: a real API-key tenant literally named like DEMO_TENANT_ID would inherit demo caps. Document in deploy.md that DEMO_TENANT_ID must be unused by real tenants.
Spend vs budget: not metered by reviewer; within ticket M budget as far as observable. Human-only .env.example additions listed in implementer findings are accepted.
