## Findings (implementer)
- Files: new `src/backend/app/core/auth.py` (mint/verify token, KeyStore Protocol, InMemoryKeyStore, issue/rotate/verify API key), `src/backend/app/api/deps.py` (`current_principal`, `current_user` now bearer-based, `get_key_store`), `core/config.py` (`auth_token_secret`), tests: new `tests/test_auth.py`, `tests/authutil.py`; `conftest.py` sets fixture secret; existing tests migrated from `X-User-Id` to `bearer(user)`; `test_api.py`/`test_t007_extra.py` auth cases rewritten.
- Contract: `Authorization: Bearer v1.<payload>.<sig>` (HMAC-SHA256, payload sub/tenant_id/iat/exp, default TTL 1h) or `Bearer dck_<key_id>_<secret>` + `X-On-Behalf-Of: <owner>`. All failures: 401 `{detail, code:"unauthorized"}` with `WWW-Authenticate: Bearer` (replaces auth_required/invalid_user_id codes). `X-User-Id` ignored. API key hash = HMAC(AUTH_TOKEN_SECRET, secret); revoked/expired/rotated keys rejected per request; last_used_at throttled to 1/min. `compare_digest` used for sigs and key hashes (dummy compare for unknown key ids).
- Edge cases: secret empty or <32 bytes -> every credential rejected (fail closed); oversize credentials rejected; ids limited to `[A-Za-z0-9_.@-]{1,64}`.
- Known gaps: key store is in-memory (Postgres store with T-026/T-029); no key admin endpoints or anonymous token mint endpoint yet; no startup failure for missing secret in non-dev (needs app-env setting, later ticket); tenant_id is not yet used to scope data (owner id remains the isolation key; tenancy tickets); spend/rate limits still keyed by owner id.
- Human-only: add to `.env.example`: `AUTH_TOKEN_SECRET=` (secret, >=32 random bytes, e.g. `openssl rand -hex 32`). Rotating it invalidates all tokens and API keys.
- See it work: `uv run pytest tests/test_auth.py -q`; full `uv run ruff check . && uv run pytest -q` passes (953+).

verdict: approve (round 1)
Checks: ruff clean, 953 tests pass. No X-User-Id reads left in src/. compare_digest used for token sigs and key hashes (dummy compare for unknown key ids). Keys stored as HMAC hash only; caplog test shows the raw key is not logged. Rotate, revoke and expiry are re-checked on every request. All failures give one uniform 401. Empty or short secret fails closed.
1. nit: src/backend/app/api/deps.py current_principal: a tenant API key may act as ANY X-On-Behalf-Of owner id, including users minted by other tenants, because owner id is still the isolation key. Disclosed as a known gap; the tenancy tickets (T-026/T-029) must bind owner ids to tenant_id before API keys ship to real tenants.
2. nit: tests/test_auth.py has no case that X-On-Behalf-Of is ignored for a user token, or that rotating an already-revoked key fails.
3. nit: `.env.example` AUTH_TOKEN_SECRET is human-only; the reviewer did not verify it was added.
