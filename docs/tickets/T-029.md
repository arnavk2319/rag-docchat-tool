- Contract: tenant comes only from the verified Principal (`current_tenant`). `for_tenant(tid)` on Registry, SessionStore, SyncVectors, SqliteParents, Bm25Store, IngestionService returns a bound view; app.state holds the unbound roots. Upload/delete paths unchanged apart from `IngestionService.for_tenant` (T-027 merge: one added method + `import copy`).
- Parents/BM25 are owner-keyed local stores: views namespace the owner key as `<tenant>:<owner>` (`:` is not a valid id char); tenant "default" = bare owner id (legacy). Existing local parents data under non-default tenants must be re-ingested.
- Spend: `SpendLedger.acquire(owner, amount, tenant=None)`; user key `<tenant>:<owner>`, tenant key `#t:<tenant>`; rate-limit bucket also `<tenant>:<user>`. Cap hit -> 429 `tenant_spend_cap_exceeded`, "Daily spend cap for your organization reached; try again after 00:00 UTC". Order: user, tenant, global.
- X-On-Behalf-Of: owner ids are only meaningful inside the key's tenant; all stores filter (tenant, owner) so another tenant's owner id yields 404 (tested).
- tenant_id fields: Document, ScoredChunk, SessionMessage models + vector_chunks/documents/sessions/session_messages tables (already in migration). "Queries" = spend ledger rows (tenant-namespaced keys) and query-path stores; no separate query model exists.
- Env var for the human to add to .env.example (I may not edit it): `TENANT_DAILY_USD_CAP=2.0` (float > 0, default 2.0; all users of one tenant per UTC day).
- Gaps: SqliteRegistry/SqliteSessions `for_tenant` return self (legacy, unused by app); tenant keys/API-key admin endpoints not in scope; Postgres paths covered by existing SQL tenant filters, not exercised against a live DB here.
