## Review (reviewer)
Verdict: changes-requested (round 1). ruff + pytest green (1069 passed, 5 skipped). Spend not reported by implementer; S ticket, diff small.
1. should - src/backend/app/api/sessions.py:19-96: unrelated reformatting of not_found, create_session decorator/body, get_session, delete_session signatures. Revert to original formatting; keep only the new code.
2. should - tests/test_sessions_api.py test_postgres_list_scoped: RecordingPool.fetchone returns None so `[0]` raises, suppressed by contextlib.suppress; only the count query is ever asserted. The main SELECT (incl. the correlated subquery tenant/owner filters, ORDER BY, LIMIT/OFFSET params) is untested. Use a pool whose fetchone returns (0,) so both queries run, and drop the suppress.
3. should - Acceptance "stored content returned HTML-escaped exactly as stream emits it (test)" is neither met nor tested; GET /{id} returns stored content (question stored raw). No test asserts either way. Either add a test pinning actual behaviour and amend the criterion in the ticket (architect/human), or escape on read.
4. nit - make_title truncates to 80 then sanitizes; escaping can grow the title past 80 chars (e.g. 80 x "&" -> 400). Cap after sanitize if "80 chars" is a hard contract (sanitize_untrusted(raw, 80) does this safely).
5. nit - no test for expired-session exclusion, nor for newest-first ordering with distinct timestamps (the in-test ordering assertion is weak if stamps tie), nor limit=100 accepted.
Checked OK: all three impls scope owner (+tenant in memory/PG; SQLite is documented legacy non-tenant), SQL parameterised, expiry filtered, total consistent with filter, 404 body identical for unknown/foreign (cross-tenant tested in-memory), no logging of content, openapi.json regenerated (drift test passes), no existing tests weakened.
Note on GET /{id}: unescaped stored content is a concern only if the frontend renders as HTML/markdown (the user's own raw question could carry markup/links; self-XSS plus defanged-link bypass). For plain-text rendering (React text nodes) it is safe, but the list title is HTML-escaped so the frontend would show literal "&lt;"; the two surfaces are inconsistent. Recommend ADR-0004 state one rule (render all as plain text, or escape both).
