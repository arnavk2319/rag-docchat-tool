### Follow-up (coordinator request): diagnosis and fixes
Retrieval trace per failing item (rank of the gold parent; BM25 / dense / fake-rerank):
- g04 "check-in time and date for the reservation" (hotel p1): before fix BM25 14, dense 3, rerank 14 (score 0.125, tied with 3 others, top is spec p13 at 0.5). After fix BM25 10, dense 3, rerank still 14. Gold child and parent ARE in the 18 fused candidates; the miss is the rerank cut. Cause: the fake reranker scores the fraction of query words found anywhere in a long spec page ("time", "date", "the"), so the short hotel page loses. Verdict (b), artifact of the fake; left alone. BM25 still ranks it only 10th because the query has no stopword filtering and function words in other chunks outscore the single "check" hit; in a larger corpus their IDF is lower, so I did not change tokenisation.
- g05 "check-out date and time" (hotel p1): before fix BM25 14, dense 16, rerank 10 (0.286; top 5 are spec pages at 0.43/0.29). After fix BM25 1, rerank 10. Retrieval now finds it first; the cut is the fake rerank again. Verdict: BM25 part was (a) REAL, fixed below; remaining miss is (b).
- g08 "room type is booked at the hotel" (hotel p2): BM25 15 -> 1, rerank rank 1 (0.333) both before and after, so retrieval and citation are right; the task failure is the toy extractive answerer picking the label line "Room Type" instead of "2 Bedroom Suite...". Verdict (b); left alone. Not part of recall.

Now one owner-wide index (cached, invalidated on add/delete), doc_ids filtering applied on scores. Regression test `test_bm25_scores_are_comparable_across_documents` (fails on the old code, passes now). Effect on mock: no metric moved (recall@5 stays 0.786 because the cut is in the fake rerank) but the retrieval stage is now correct for g05 and g08.
